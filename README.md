# PYQ Studio

A static JEE previous-year-question practice workspace. Serve the repository root with any static web server (for example, `python3 -m http.server 4173`) and open the served page. The chapter question bank is available as ordinary JSON files under `data/`, extracted from the checked-in `data.zip`, so standard static hosting can load each file directly. `data/papers.json` indexes chapter-bank papers, while `data/exact-papers.json` is a generated catalog for `jee-main-papers-by-year.zip`—the source-of-truth archive for original JEE Main papers from 2012–2026. Both catalogs are also included in `data.zip` for hosts that omit the extracted `/data` directory; full year files are read from the year-wise ZIP at runtime.

## Practice experience

- Practice and custom tests use randomized, topic/difficulty-balanced selection. Chapter sessions prefer newer exam years while remaining random within a year; questions you have not seen are preferred, and the least-recently-seen questions return when a pool is exhausted.
- Test Studio can launch an exact full-paper PYQ mock: choose an available year and shift for JEE Main, or Paper 1 / Paper 2 for JEE Advanced. JEE Main papers covered by `jee-main-papers-by-year.zip` are read directly from that archive in their exact source `position`/subject order, with the original question HTML, MathJax SVG, options, answer keys, and worked solutions. JEE Main sittings not represented in the archive and all JEE Advanced papers use the chapter bank in JEE section order—MCQs first followed by numerical-value questions for Physics, Chemistry, and Mathematics. Range, alternate-value, dropped, and bonus answer keys from the archive are preserved and left unscored instead of being marked wrong. Every exact mock uses the selected sitting’s complete question set rather than a randomized sample and runs in the existing timed, autosaved exam flow.
- Timed tests use a clean exam layout that hides question-bank tags, save/report controls, and practice tips, and request browser fullscreen when permitted. An in-app exam view remains available if fullscreen is blocked. Unfinished tests autosave answers, review marks, the current question, and an absolute deadline so the remaining time is preserved across reloads. Resume or discard a saved test from Overview or Test Studio.
- Incorrect and skipped questions enter a spaced-review queue. Misses come back the next day; successful reviews expand through 1, 3, 7, 14, 30, 60, and 90-day intervals. Due questions can be launched as a focused review session.
- Adaptive daily and weak-topic practice prioritizes due reviews, then blends lower-accuracy topics with general questions and adjusts difficulty preference to recent performance.
- Progress analytics show per-topic accuracy and a short-term trend (latest five scored answers versus the previous five). Submitting a test (or opening any completed test from Test Studio or Progress history) launches a dedicated fullscreen, mobile-compatible test analysis screen with overall score, positive/negative marks, subject-wise marks and accuracy (including MCQ vs numerical splits), chapter and topic breakdowns, difficulty analysis, pacing/stamina comparison, an interactive paper response grid, and question-by-question solution inspection—using the existing local storage format unchanged. Topics with at least three recent scored answers and accuracy below 65% also get a focused-practice recommendation.
- Save reusable test-builder setups for chapter selection, question count, time, year, and difficulty.
- Flag a possible answer-key, solution, diagram, duplicate, or other question issue from the question view. Reports are stored locally and included in workspace backups; they are not uploaded automatically.
- Keyboard controls: left/right arrows move between questions, 1–4 select an answer, M toggles a test review mark, C clears the current test answer, and Enter advances (or opens the final-submit prompt). Shortcuts pause while a modal or text field is active.
- A persistent light/dark theme toggle remembers the student’s choice and restyles the full workspace, dialogs, analytics cards, and timed-test controls.
- Chapter selection opens a dedicated workspace instead of a dialog. Practice sessions use a focused viewport with global navigation hidden; on small screens, primary destinations use a thumb-friendly bottom bar, dialogs become bottom sheets, controls respect device safe areas, and test/practice question navigation stays in a compact bottom dock.
- Question, solution, and answer-option diagrams load lazily with asynchronous decoding, scale to the available desktop/mobile viewport, and show an accessible fallback when a source image cannot load.

## Exact JEE Main paper archive

- `jee-main-papers-by-year.zip` contains 192 complete papers and 13,981 answered questions. Each question carries its original paper position, subject number, HTML/MathJax content, options, answer key, tags, source link, and worked solution.
- `tools/generate_exact_paper_catalog.py --update-data-zip` regenerates `data/exact-papers.json`, `assets/exact-paper-catalog.mjs`, and the `data.zip` fallback entry from that archive. The app prefers a loose `/data/exact-papers/<year>.json` file if a deployment extracts one, then reads the selected year from the checked-in ZIP.
- Shared MathJax SVG path definitions are installed once in a hidden SVG host when a paper is opened. The rich-text sanitizer preserves the archive’s `mjx-container`, `use`, and SVG data attributes while still forbidding scripts, iframes, and `srcset`.
- Completed exact-paper tests (archive and chapter-bank papers) store compact response references rather than repeating megabytes of HTML in local storage. Opening analytics, reviewing answers, or resuming an unfinished test rehydrates the full questions and solutions from the saved offline copy (when present) or from the ZIP / chapter files.
- `tools/patch_bundle.py` records the source-level changes applied to the checked-in minified React bundle; it is safe to rerun after a checkout.

## Offline papers, images, and reliable local storage

- **Download & save offline** sits under the exact-paper picker. It loads the complete paper, downloads every embedded diagram (question text, options, `question_image`, solutions, `<picture>`/`srcset`/`data-orsrc` variants), and stores the questions, MathJax definitions, and image blobs in IndexedDB (`pyq-offline`). Papers saved this way show a “saved offline” note in the shift selector.
- Offline mocks are real mocks: the same +4 / −1 scoring, timer, autosave, analytics, and result screen run with no network. Answers, unfinished sessions, and completed tests are unaffected by connectivity because cached questions are loaded before any archive request, and readable images are rendered through `blob:` URLs. A CDN that refuses CORS is retried without CORS; its opaque response is saved in Cache Storage and served at the original image URL by the service worker. Its size and HTTP status cannot be verified.
- The download also offers a portable **paper file**: a self-contained `.html` (answer key, every question, option diagram, and expandable worked solution, with images embedded as data URLs) and a `.json` bundle with the same content. Only readable images can be embedded in exports; opaque or missing images keep their online URLs.
- Downloads report per-image progress and can be cancelled. Images that fail (offline mid-download, dead CDN URL) are listed and can be retried later without discarding the rest of the paper; IndexedDB quota pressure evicts the oldest saved paper rather than losing the new one.
- **Settings → Offline papers** shows saved papers, image counts, and storage used, offers “Keep offline data” (persistent storage) and per-paper removal, and can clear the whole offline cache. It is separate from the progress backup, which still exports the workspace as JSON.
- Progress and settings use a more defensive local-storage layer: each write is checksummed and versioned, the previous good payload is kept as `pyq-studio-v1:backup`, a corrupted primary is recovered from that backup on load, and writes are debounced (300 ms) with a flush on `pagehide`/`visibilitychange` so the last answer is never lost. Legacy `pyq-studio-v1` payloads are migrated in place, so existing workspaces keep working and the backup format is unchanged.
- Offline, the exact-paper picker opens on the most recently saved paper, and years and shifts saved on the device are marked “saved offline”. Saved papers stay selectable even if the paper index was never cached. Starting a paper that is not on the device explains that instead of showing the browser’s raw `NetworkError when attempting to fetch resource.` / `Failed to fetch`. **Retry images** reuses the saved questions and is disabled while offline.
- `sw.js` precaches the app shell (`index.html`, bundle, feature modules, CSS, fonts, favicon) and the boot indexes. It serves navigations network-first with a cached-shell fallback, which also kicks in after 4 s on a connection that hangs. It caches the year-wise and chapter ZIPs plus `data/` JSON for offline use, and keeps recently used diagrams in a bounded image cache.
  - Only the shell caches (`pyq-shell-<VERSION>`, `pyq-runtime-<VERSION>`) are tied to a release. `pyq-data-v1`, `pyq-images-v1` and `pyq-paper-images-v1` survive updates, so shipping a new version never wipes data a learner relies on offline. Entries from older `pyq-data-<VERSION>` caches are migrated on activation. JSON is revalidated in the background, and a cached ZIP is revalidated once per `VERSION` with a conditional request.
  - The core shell is precached all-or-nothing. If any core file fails to download, the update is abandoned and the previous version keeps working offline.
  - Shell responses are stored and served without redirects, so hosts with "pretty URLs" (Cloudflare Pages redirects `/index.html` to `/`) still open offline. Browsers refuse a redirected response for a page load.
  - A request that is neither reachable nor cached gets a `503` marked `X-PYQ-Offline: 1` (never a rejected `respondWith`). The app turns that into a readable offline message.
  - Bump `VERSION` in `sw.js` when shipping new assets so clients pick up the new shell. `manifest.webmanifest` lets the app be installed to the home screen.
- Offline use needs a service worker. Firefox private windows (and browsers with site data disabled) don’t run service workers, so the app can’t open there without a connection, even after a paper was downloaded.

Export a workspace backup before moving to another device (offline papers are device-local and are not part of the backup). Run `npm ci && npm test` for the regression suite (jsdom is used only by the rich-text rendering test).
